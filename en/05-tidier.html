5  Data wrangling with Tidier

In the original book this is the tidyverse chapter. Julia has a remarkably faithful translation: the Tidier family, a pure-Julia reimplementation of the tidyverse mini-language on top of DataFrames.jl.

using TidierData
using DataFrames
using Statistics

5.2 @chain: the pipe

@chain is the backbone of everything that follows. It passes each line’s result as the first argument of the next — exactly the role of |> (or %>%) in R.

@chain ponds begin
    @filter(region == "Amazon")
    @select(pond_id, area_m2, canopy, richness)
    @arrange(desc(richness))
    first(5)
end

ponds %>%
  filter(region == "Amazon") %>%
  select(pond_id, area_m2, canopy, richness) %>%
  arrange(desc(richness)) %>%
  head(5)

The correspondence is line for line. The only syntactic difference is the @ and the begin ... end.

5.3 The five verbs

5.3.1 @filter — pick rows

@chain ponds begin
    @filter(richness > 8 && hydro == "permanent")
    nrow
end
39

Note: inside @filter, use && and ||, not & and | as in dplyr.

NoteYour turn 5.2 — Several conditions at once

How many temporary ponds have canopy cover above 60% and richness below the overall median richness? Check the number with check("5.2", n).

TipHint

Compute the median first, outside the chain: med = median(ponds.richness). Inside a Tidier macro a bare name means a column, so to use the variable med write !!med.

If you get TypeError: non-boolean (Missing) used in boolean context, some ponds have no canopy value, and missing > 60 is neither true nor false. Remove those rows first with @drop_missing(canopy) (Section 5.4).

CautionSolution 
med = median(ponds.richness)

n = @chain ponds begin
    @drop_missing(canopy)
    @filter(hydro == "temporary" && canopy > 60 && richness < !!med)
    nrow
end
18
check("5.2", n)
✓ Correct!

Dropping ponds without canopy is the right call here: we cannot know whether their canopy is above 60%. The median, though, is computed on all 180 ponds, before dropping anything.

NoteYour turn 5.4 — Where is the focal species?

Compute, for each region, the proportion of ponds where the focal species occurs, in a column called prop_focal, sorted from highest to lowest. Check it with check("5.4", by_region).

TipHint

focal is 0 or 1, so its mean is the proportion of ponds where it is 1. Sorting from highest to lowest is @arrange(desc(...)).

CautionSolution 
by_region = @chain ponds begin
    @group_by(region)
    @summarize(prop_focal = mean(focal))
    @arrange(desc(prop_focal))
end

check("5.4", by_region)
✓ Correct!

5.4 Missing data

The canopy column has missing values on purpose.

sum(ismissing.(ponds.canopy))
7
@chain ponds begin
    @drop_missing(canopy)
    nrow
end
173
# aggregating while ignoring missings
@chain ponds begin
    @group_by(region)
    @summarize(mean_canopy = mean(skipmissing(canopy)))
end
3×2 DataFrame
Row region mean_canopy
String15 Float64
1 Atlantic 51.7125
2 Amazon 45.313
3 Cerrado 49.327
Warning

mean(canopy) returns missing if any value is missing — the same behaviour as R’s mean() without na.rm = TRUE. Be explicit with skipmissing.

NoteYour turn 5.5 — Where are the gaps?

Before dropping missing values, it is worth knowing where they are: if they concentrate in one region, dropping them changes that region more than the others. Count, per region, how many ponds have no canopy value, in a column called n_missing. Check it with check("5.5", gaps).

TipHint

ismissing.(canopy) gives true for each missing value, and sum counts the trues. Both work inside @summarize.

CautionSolution 
gaps = @chain ponds begin
    @group_by(region)
    @summarize(n_missing = sum(ismissing.(canopy)))
end

check("5.5", gaps)
✓ Correct!

Seven missing values spread over three regions: no region is hit much harder than the others, so dropping them is unlikely to bias comparisons between regions.

NoteYour turn 5.6 — Forest versus savanna

Using the regions table above, compute the mean richness of forest and savanna ponds, in a column called mean_rich. Check it with check("5.6", by_biome).

TipHint

Join first, so every pond gets its biome_type; then group by biome_type and summarize.

CautionSolution 
by_biome = @chain ponds begin
    @left_join(regions, region)
    @group_by(biome_type)
    @summarize(mean_rich = mean(richness))
end

check("5.6", by_biome)
✓ Correct!

5.7 DataFrames.jl underneath

Tidier is a convenience layer. It is worth knowing the native form, which is what you will meet in most of the ecosystem’s documentation:

combine(
    groupby(ponds, :region),
    :richness => mean => :mean_rich,
    :richness => length => :n,
)
3×3 DataFrame
Row region mean_rich n
String15 Float64 Int64
1 Atlantic 6.59091 66
2 Amazon 11.1042 48
3 Cerrado 4.78788 66

Same result as the @group_by/@summarize above. Use Tidier to write, and recognize the native form to read.

NoteYour turn 5.7 — The same, natively

Rewrite your answer to 5.4 with groupby, combine and sort from DataFrames.jl, without Tidier macros. Check it with check("5.7", by_region_native).

TipHint

sort(df, :col, rev = true) sorts from highest to lowest.

CautionSolution 
by_region_native = sort(
    combine(groupby(ponds, :region), :focal => mean => :prop_focal),
    :prop_focal, rev = true)

check("5.7", by_region_native)

Challenges

These have no checker. They are about what the numbers do — and do not — tell you.

  1. In 5.4 the Cerrado comes first, but the three proportions only range from 0.42 to 0.48, each from 48 to 66 ponds. Open scripts/make_data.jl: does region affect the focal species in the simulation? What does that tell you about reading a ranking off a summary table?
  2. In 5.6 forest ponds are richer than savanna ponds. But “forest” here means Atlantic plus Amazon. Compute mean richness per region and decide whether “forest” is a useful grouping for this question.
  3. Use @pivot_longer to put area_m2, canopy and temp_c in one column, then compute the mean of each variable per region in a single pipeline. How do you deal with the missing canopy values?
